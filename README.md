# 너구리 만물상

조선시대 마을의 무너진 가게를 하나씩 되살리는 방치형 타이쿤.

## 왜 이 소재인가

방치형의 진행은 보통 숫자가 커지는 것뿐이다. 여기서는 **마을이 복구되는 것**이 진행이다.
가게 자리 다섯 개가 처음엔 전부 폐허고, 대장간 하나만 살아있다. 돈이 모이면 옆집이
문을 열고, 폐허 자리에 지붕이 올라간다. 숫자가 아니라 풍경이 바뀐다.

소재는 전부 조선이다 — 곡괭이·낫·붓·먹·한지·옹기·산삼. 시대를 하나로 묶으면
품목을 늘릴 때 "이 다음에 뭐가 오지"가 저절로 정해진다.

## 구조

```
품목 칸 = 자동 생산 → 재고 → 손님이 사감 → 돈 → 새 품목 / 새 가게
```

**손님이 다음 목표를 지정한다.** 방치형의 고질병은 "뭘 사야 할지 모르겠다"인데,
손님이 없는 물건을 물어보면(`토끼: "곡괭이 있소?"`) 그 순간 그게 답이 된다.
물어본 적 없는 품목은 `? ? ?`로 잠겨 있고, 열 수조차 없다.

요청은 **한 번에 하나만** 띄운다(`sim.js:_ask`). 요청이 3개씩 쌓이면 목표를 하나로
좁히려던 이유가 그대로 무너지기 때문이다.

### 성장의 축

목록형 방치형은 축이 하나(레벨업)라 한 시간이면 바닥이 보인다. 여기엔 여섯 개가 있다.

| 축 | 무엇이 늘어나나 | 어디에 |
|---|---|---|
| 품목 강화 | 값·생산속도 | `LEVEL`, `MILESTONE_EVERY` |
| 가게 해금 | 새 품목 줄 | `SHOPS[].cost` |
| 가게 승급 | 물건 자체가 진화 (돌도끼 → 쇠도끼) | `SHOPS[].ranks/promote`, `RANKS` |
| 손님 등장 | 수요 | `GUESTS[].at` |
| 단골 등급 | 손님 한 명의 씀씀이 | `REGULARS` |
| 곁가게 | 터치 버프 | `SMALL_SHOPS` |
| 나쁜 놈들 | 손가락으로 잡는 보상 | `PESTS` |
| 삽살개 | 자리를 비운 사이를 맡는다 | `GUARD` |

가게 승급은 **문 하나가 아니라 계단**이다 — 그 가게 물건 전부 만렙 + 앞 가게 승급 +
손님 수 + 초당 매출 + 돈, 다섯 조건을 같이 본다(`sim.js:promoteReqs`).

### 손님마다 성격이 있다

예전엔 `every·qty·pay`가 뒤로 갈수록 나란히 커져서 나중 손님이 앞 손님의 상위호환이었다.
지금은 잘하는 것과 못하는 것이 갈린다(`content.js:GUESTS`).

```
every   오는 간격(초)      qty  한 번에 사가는 개수
pay     부르는 값 배수     spread  훑는 품목 종류 수 (1이면 한 종류를 쓸어간다 = 품절)
speed   걷는 속도 배수 (화면에서만)
```

까치는 3.1초마다 오지만 값을 0.85배로 깎고, 거북은 110초마다 오지만 7배로 쳐준다.
멧돼지·곰은 `spread:1`이라 진열대 한 칸을 통째로 비우고 간다.

## 파일

```
content.js   내용물 전부 — 가게·품목·손님·단골·곁가게·레벨 공식
sim.js       경제 로직. 그리기 코드가 한 줄도 없다
scene.js     마을 장면. 경제 코드가 한 줄도 없다
art.js       그림을 끼우는 자리. 그림이 없으면 이모지로 넘어간다
index.html   화면 뼈대 · 헤더 · 아래 창(가게 / 손님 도감)
art/         PNG를 여기 놓기만 하면 들어간다 (ASSETS.md)
tools/       balance.mjs 밸런스 측정 · bundle.mjs 한 파일로 묶기
core/        shipyard에서 가져온 공용 레이어
```

로직과 렌더링을 분리한 이유: **방치형은 성장 곡선이 곧 게임이다.**
브라우저를 띄워야만 확인이 되면 하루에 몇 번 못 돌려본다.

### 마을 사람

**사장은 플레이어다.** 화면에 사장 너구리는 없다 — 마을을 보고 있는 사람이
곧 사장이다.

가게마다 **점장 너구리**가 하나씩 붙는다(`scene.js`의 `_mgr` · `_clerk`).
평소엔 작업대에서 만들고, 손님이 오면 몇 걸음 나가 건네고, 진열대가 꽉 차
생산이 멈추면 **존다**(💤).

정확한 진행은 캐릭터가 아니라 **좌판 칸의 고리**가 알린다. 가운데 숫자는
쌓인 개수, 두른 고리는 다음 한 개까지 남은 정도(`prog / craftTime`)다.
그래서 강화하면 고리가 눈에 띄게 빨리 돈다 — 지금까지 강화는 숫자만
바뀌고 화면은 그대로였다.

**경제에는 아무 영향이 없다** — sim이 이미 아는 상태를 화면이 읽어서 그릴 뿐이다.

### 화면

캔버스 한 장에 마을을 그린다(`scene.js`). 가상 좌표 가로 480 · 세로 1750을
**가로에 맞춰**(`engine.js`의 `fit:'width'`) 늘리고, 세로는 기기가 주는 만큼 보여준 뒤
나머지는 손가락으로 밀어 본다. 그래서 아이폰 SE부터 갤럭시 폴드 펼친 화면까지
검은 여백 없이 같은 그림이 나온다. 폴드처럼 화면이 도중에 바뀌면 보던 지점을
가운데 기준으로 다시 잡는다(`_camera`).

## 밸런싱

```bash
node tools/balance.mjs 8       # 8시간 연속 플레이를 몇 초에
node tools/balance.mjs 1       # 신규 유저의 첫 1시간
node tools/balance.mjs 8 7     # 같은 8시간을 다른 씨앗으로 (재현 가능)
```

숫자만 바꿔가며 수백 번 돌려본 뒤에 그림을 그린다. 반대로 하면 되돌릴 수 없다.

### 재는 법 (뼈저리게 배운 것)

- **평균은 거짓말을 한다.** 진열대 평균 재고가 "19.7/40, 딱 중간"이어도 시간대별로
  보면 앞 네 시간 36~39, 뒤 네 시간 0.7인 경우가 있다. 언제나 **시간대별로 쪼개서** 본다.
- **검사 도구부터 검사한다.** `every`로 정지를 판정하던 시절엔 품목 7개가 죽어 있는데도
  "생산 정지 0.0%"가 나왔다. 새 지표를 만들면 먼저 답을 아는 대조군으로 확인한다.
- **가상 플레이어가 헛짓을 하면 지표가 오염된다.** 만렙 품목을 계속 클릭해서
  "클릭 간격 0.3초 = 긴장 없음"이 나온 적이 있다. 실제로는 6.0초였다.

### 현재 지표 (10시간, 씨앗 1)

```
죽은 품목 0 · 가게 5곳 전부 해금 · 승급 8회
새 손님 12명이 0분 ~ 7시간대에 걸쳐 등장
진열대 평균 재고 22~25 / 40 · 못 사고 간 손님 1%
나쁜 놈: 안 잡으면 -0.87% · 삽살개에 맡기면 +1.2% · 직접 매번 잡으면 +13.9%
콘텐츠 소진 9시간24분
```
