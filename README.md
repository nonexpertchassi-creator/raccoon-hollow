# 너구리 만물상

조선시대 마을의 무너진 가게를 하나씩 되살리는 방치형 타이쿤.

## 왜 이 소재인가

방치형의 진행은 보통 숫자가 커지는 것뿐이다. 여기서는 **마을이 복구되는 것**이 진행이다.
가게 자리 다섯 개가 처음엔 전부 폐허고, 대장간 하나만 살아있다. 돈이 모이면 옆집이
문을 열고, 마을 화면의 `□`가 간판으로 바뀐다. 숫자가 아니라 풍경이 바뀐다.

소재는 전부 조선이다 — 곡괭이·낫·붓·먹·한지·옹기·산삼. 시대를 하나로 묶으면
품목을 늘릴 때 "이 다음에 뭐가 오지"가 저절로 정해진다.

## 구조

```
품목 칸 = 자동 생산 → 재고 → 손님이 사감 → 돈 → 새 품목 / 새 가게
```

**손님이 다음 목표를 지정한다.** 방치형의 고질병은 "뭘 사야 할지 모르겠다"인데,
손님이 없는 물건을 물어보면(`토끼: "곡괭이 있소?"`) 그 순간 그게 답이 된다.
물어본 적 없는 품목은 `? ? ?`로 잠겨 있고, 열 수조차 없다.

요청은 **한 번에 하나만** 띄운다(`sim.js:_ask`). 요청이 3개씩 쌓이면 목표를 하나로
좁히려던 이유가 그대로 무너지기 때문이다.

## 파일

```
content.js   내용물 전부 — 가게·품목·손님·레벨 공식
sim.js       경제 로직. 그리기 코드가 한 줄도 없다
index.html   화면 전부. DOM 렌더 단일 파일
tools/       balance.mjs — 브라우저 없이 게임 수백 시간을 몇 초에 돌린다
core/        shipyard에서 가져온 공용 레이어 (store · juice 사용 중)
```

로직과 렌더링을 분리한 이유: **방치형은 성장 곡선이 곧 게임이다.**
브라우저를 띄워야만 확인이 되면 하루에 몇 번 못 돌려본다.

### core/ 연결 상태

| 파일 | 상태 |
|---|---|
| `store.js` | ✅ 저장/로드에 사용 |
| `juice.js` | ✅ 소리·흔들림에 사용 |
| `engine.js` | ⬜ 미연결 — 캔버스 엔진인데 이 게임은 DOM 렌더 |
| `telemetry.js` | ⬜ 미연결 |
| `ui.js` | ⬜ 미연결 — 광고/상점 오버레이 |

## 밸런싱

```bash
node tools/balance.mjs 6     # 6시간 연속 플레이를 몇 초에
node tools/balance.mjs 1     # 신규 유저의 첫 1시간
```

숫자만 바꿔가며 수백 번 돌려본 뒤에 그림을 그린다. 반대로 하면 되돌릴 수 없다.

### 알려진 문제

- **하위 품목이 죽는다.** 손님이 재고 중 최고가 품목 한 종류만 사가서(`_buy`),
  하위 품목은 재고 상한 40에 박혀 생산까지 멈춘다. 2시간 시점에 12개 중 7개가 이 상태다.
- **`balance.mjs`가 그걸 못 잡는다.** 정지 판정이 `every`라 *전부* 꽉 차야 세는데,
  상위 품목은 계속 팔리므로 영원히 0%로 보고된다.
- **행동의 99%가 레벨업이다.** 2시간에 레벨업 1315회 대 의미 있는 선택 11회.
