## 1. Discussion — 콘셉트 이미지와 게임 에셋의 차이

승인된 P01은 건물, 지면, 캐릭터, 그림자가 한 장에 합쳐진 아트 방향 이미지다. 현재 게임은 상점 해금, 손님 증가, 건물 진입이 실시간 상태에 따라 바뀌므로 P01 자체를 게임 배경으로 넣으면 진행 상태를 분리해 표현할 수 없다.

따라서 P01은 색감·건축·재료·분위기 레퍼런스로 사용하고, 게임에는 상태별로 교체 가능한 독립 요소가 필요하다.

## 2. Decision — 유지할 게임 구조

- 경제 계산, 저장, 상점 해금 로직은 변경하지 않는다.
- 기존 상점 상세 탭과 품목 카드는 유지한다.
- `마을` 탭만 실제 진행 상태가 보이는 비주얼 맵으로 바꾼다.
- 열린 건물을 누르면 기존 상점 상세 탭으로 들어간다.
- 다음 복구 건물은 비용과 함께 직접 누를 수 있다.
- 화면은 현재 게임의 최대 폭 480px과 세로 모바일 뷰포트 안에서 작동해야 한다.

## 3. Hypothesis — Village Map V0.1

- 흙길을 마을의 복구 진행선으로 사용한다.
- 다섯 건물을 길을 따라 엇갈리게 배치한다.
- 건물은 `영업 중 / 다음 복구 / 잠김` 세 상태로 표현한다.
- 복구된 건물 주변에는 녹색 기운과 깨끗한 색을 조금 되돌린다.
- 상단에는 마을 복구 수와 장부 정리를 두고, 하단에는 다음 목표와 최근 소식을 둔다.
- CSS/DOM 건물과 점주는 화면 구조 검증용 임시 표현이며 최종 아트로 확정하지 않는다.

## 4. 현재 구현 연결

| 게임 상태 | 화면 표현 | 상호작용 |
|---|---|---|
| `sim.shops`에 포함 | 복구된 지붕, 밝은 벽, 녹색 접지 | 누르면 기존 상점 탭 진입 |
| `sim.nextShop()` | 밝게 강조된 폐허와 복구 비용 | 돈이 충분하면 눌러 복구 |
| 그 이후 상점 | 채도와 대비가 낮은 폐허 | 비활성 |
| `sim.guests` | 최근 해금 손님 최대 3마리 | 작은 방문객 표시 |
| `sim.auto` | 장부 정리 완료 상태 | 자동 강화 상태 표시 |

## 5. 실제 제작 에셋 분리 순서

맵 구조가 승인되면 다음 순서로 CSS 임시 그림을 교체한다.

1. 건물과 캐릭터가 없는 세로형 지면/길 배경
2. 공통 폐허 건물 투명 PNG
3. 복구된 기본 건물 투명 PNG
4. 실제 플레이 크기의 한국 너구리 점주 스프라이트
5. 손님 동물 스프라이트
6. 장독, 지게, 광주리, 식생 등 독립 소품
7. 개별 전문 상점 외형

모든 건물은 같은 카메라, 같은 바닥 접점, 같은 외곽선 밀도를 공유해야 한다.
